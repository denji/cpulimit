Limit the CPU of a process without touching its priority.

cpulimit alternates SIGSTOP and SIGCONT within short chunks and corrects the duty cycle from the CPU time the target actually used, so the limit follows system load. Made for batch jobs that must not eat the machine.

Install Source Architecture

Version 1.0.1 · GPL-2.0-or-later · release notes

# an existing process: half a CPU
cpulimit -l 50 -p 1234
# by name, with its children
cpulimit -l 25 -i -e ffmpeg
# start a command and limit it; the exit status is the command's
cpulimit -l 80 -- make -j8
# background daemon with syslog and a pid file
cpulimit -d -s -P /run/cpulimit.pid -l 30 -e backup

Install

GNU make and a C compiler. Use gmake on the BSDs and illumos. The build is non-recursive, keeps objects in build/, rebuilds when flags change and never overrides your CFLAGS.

make && sudo make install
# PREFIX=/usr/local; DESTDIR=, BINDIR=, MANDIR= honoured
make check
# unit, CLI and integration tests
make static STATIC_CC=musl-gcc
# static binary in build/static/

Usage

Exactly one target: -p PID, -e NAME_OR_PATH or a COMMAND [ARGS]. Full details, exit statuses and signals: man cpulimit.

How it works

Each chunk (100 ms by default) is split into a run slice and a stop slice. After every chunk the controller compares the CPU time the target really used with the limit and adjusts the next split.

Process identity

Targets are tracked by pid and start time, so a recycled pid is not limited by mistake.

Safe signals

The handler only sets a flag. Signals are blocked except inside pselect(), so there is no lost-wakeup window. SIGINT/TERM/HUP/QUIT release every limited process and exit 0.

Monotonic clock

Timing uses CLOCK_MONOTONIC, so wall-clock steps cannot distort the duty cycle.

Never strand a target

Every code path that stops a process has a matching continue, including exit and error paths. Controller invariants are in ARCHITECTURE.md.

What's new

Compared with the original code base. Log lines, exit statuses and -p -e -l -c -i -m -v -z are kept for existing scripts. Features from issue #1.

Daemon mode

-d double-forks and detaches; -P writes a pid file and refuses to start when a live one exists.

Syslog

-s sends every log line to syslog in addition to the console output, with the matching priority.

One limiter per target

A second cpulimit on the same process is refused (exit 1) and names the first, since two limiters undo each other. It is an fcntl record lock, so it disappears with its holder even on SIGKILL. --no-lock overrides.

Command mode is one process

cpulimit -l 50 cmd forks the command and runs the loop itself. The exit status is the command's; no separate limiter is left behind.

Strict options

Long options and range-checked numbers: -l 5x and -l abc are rejected, -m no longer crashes, a zero or huge chunk size no longer spins.

Less kernel time

The Linux /proc reader parses strictly and reads the command only when needed. In one run on a 2-CPU VM: 215 → 88 syscalls/s for one target; limiter CPU 4.9% → 2.4% with 200 children under -i.

Static builds

make static with musl; CI cross-builds and tests on arm64, armv7, i386, ppc64le, s390x, riscv64 under qemu.

Build and docs

One non-recursive Makefile, GitHub Actions instead of Travis, a man page, and an architecture document.

Accuracy is not improved. Both versions use the same controller and both under-deliver at low limits and overshoot near 50%. The gains are overhead and correctness. See Measurements.

Measurements

Every number is in data/results.json with where and when it was measured, and the charts are generated from that file by tools/charts.py. They are single runs on a 2-CPU virtual machine with a 10 ms clock tick: treat differences of a point or two as noise.

Known limitations

  • If cpulimit is killed with SIGKILL (or by the OOM killer) during a stop slice, the target stays stopped. Send it SIGCONT.
  • A pid can be recycled between reading a process and signalling it. Start-time identity closes the long window; one control cycle remains.
  • A multi-threaded target is limited as a whole, not per thread.
  • -m is a fraction of a CPU (0.05) while -l is a percentage.

Releases

Full history: CHANGELOG.md. The command-line interface and the exit statuses in man cpulimit are the public interface that 1.x keeps stable.

1.0.1 2026-10-22

The bounded model checker found a real defect: compute_slices() computed 0 / NaN and cleaned it up afterwards. It now never produces a NaN; the result is identical for every input. Verification harnesses reworked. No change to options, exit statuses or log text.

1.0.0 2026-10-21

First release of the fork: daemon mode, syslog, pid file, single-limiter lock, single-process command mode, strict option parsing, pid + start-time identity, a rewritten /proc reader, a non-recursive build, GitHub Actions instead of Travis.
